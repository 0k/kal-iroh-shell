#+TITLE: kal-iroh-shell

Thin app shells whose interface lives on the server: the app on each
device shows the interface its server publishes, and reloads it — what
the user was doing saved — the moment a new version is published.

* What it is

An app built with it (a Tauri or GTK program with a WebView) does not
need a new package to change its interface.  The interface is a Vite
build published on the server; every device follows a control stream
and reloads into the new version, without a button and without polling.

Three parts:

| Part                       | Runs where                         | What it does                                                                                       |
|----------------------------+------------------------------------+----------------------------------------------------------------------------------------------------|
| =kal-iroh-shell=           | inside the app, on each device     | serves the page from the current release (built-in copy as fallback), follows the control stream, runs the reload handshake |
| =kal-iroh-shell-server=    | on the server                      | serves the publish directory and a =kal-sse= control stream announcing each release and the files that changed |
| =@0k/kal-iroh-shell= (npm) | in the page and in the Vite build  | page side of the handshake (save, busy, restore focus) and the Vite plugin that publishes releases; its own repository, [[https://github.com/0k/kal-iroh-shell-js][kal-iroh-shell-js]] |

=kal-iroh-shell-protocol= holds the wire formats all three share.

* Releases and channels

Releases live in a *release store*, a bare git repository holding only
built interfaces:

- a release is a commit of one finished build;
- a channel is a branch: =dev=, =alpha=, =beta=, =stable=, or any other
  name (the set is open);
- publishing adds a commit on top of a channel; promoting moves a
  channel to any release, forwards or backwards (every move stays in
  the reflog, so it can be undone);
- a device follows exactly one channel.

* How an update flows

1. =kal-iroh-shell-releases publish --channel dev dist= commits the
   build on top of =dev= (or =promote= moves a channel).
2. =kal-iroh-shell-releases serve= sees the ref move and appends an
   event ={channel, commit, build_id, previous, changed, removed}= to
   its control stream.
3. A reverse proxy (for example a vigil-watch serve mount reached over
   Iroh) carries the stream to the devices.
4. A shell following that channel sees a release the page does not run
   and asks the page to prepare: =window.__kalIrohShell.prepareReload(n)=.
5. The page saves what is not saved yet and answers =ready=, or =busy=
   with a reason while the user is recording, uploading or sending; it
   renews =busy= and turns =ready= as soon as it can.
6. The shell reloads the view natively.  A page that does not answer
   within 5 s, or stops renewing =busy= for 30 s, is reloaded anyway.

* Usage

** Server

#+begin_src sh
S=~/.local/share/my-app-releases.git
kal-iroh-shell-releases --store $S publish --channel dev frontend/dist   # creates the store
kal-iroh-shell-releases --store $S promote dev alpha        # alpha ← what dev has
kal-iroh-shell-releases --store $S promote 20261030T085038-b066f8 beta   # by build id
kal-iroh-shell-releases --store $S promote stable~1 stable  # undo the last stable move
kal-iroh-shell-releases --store $S channels                 # where each channel points
kal-iroh-shell-releases --store $S log beta                 # history of a channel
kal-iroh-shell-releases --store $S -v serve
#+end_src

=serve= listens on =127.0.0.1:4310= by default (=--listen=) and must be
reachable by the devices below a path prefix, for example through a
reverse proxy at =/serve/my-app/=.  =--store= can also be given as
=$KAL_IROH_SHELL_RELEASES_STORE=.

** Build

#+begin_src ts
// vite.config.ts
import { kalIrohShellRelease } from '@0k/kal-iroh-shell/vite';

export default defineConfig({
  plugins: [vue(), kalIrohShellRelease()],
});
#+end_src

The plugin only writes =ui-manifest.json= into the build; publishing is
the explicit =publish= command above.

** Page

#+begin_src ts
import { installShellReload, restoreViewState, useShellBusy, useShellReloadSave } from '@0k/kal-iroh-shell';

installShellReload();               // before mounting
app.mount('#app');
restoreViewState();                 // refocus the field the user was in

// in components / composables:
useShellReloadSave(() => flushDraft());
useShellBusy('microphone on', () => recording.value);
#+end_src

** App (Rust)

The app implements =Host= (where its server is, credentials, admission,
the user's setting), builds a =RemoteUi=, merges =RemoteUi::routes()=
into its local server, serves its page through =RemoteUi::index()=
(adding =ServedUi::root_attributes()= to the root element), calls
=RemoteUi::spawn()=, and executes =ShellCommand=s on its view (feature
=tauri=: =tauri::run_shell_commands=).

See [[file:doc/adopting.org][doc/adopting.org]] for the complete steps, both ways.

* Delivery

Rust crates: git dependency on this repository, pinned to a revision.
npm package: =npm install @0k/kal-iroh-shell= (published from
[[https://github.com/0k/kal-iroh-shell-js][kal-iroh-shell-js]]).
